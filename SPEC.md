# SPEC — тестовое snapbuild

Спека для воспроизведения лендинга snapbuild.ru и добавления пяти новых секций.
Стек: React + Vite + Tailwind, FSD (`app / widgets / shared`), деплой на GitHub Pages.

---

## 0. Главное, что нужно понять до первой строчки кода

### 0.1. В CSS сайта два слоя, живой только один

| Слой | Что это | Использовать? |
|---|---|---|
| Tailwind v4 + `.card` / `.pricing-card` / `.testimonial-card` / `.btn-primary` | база шаблона | **НЕТ** |
| `dds-*` / `sds-*` | реальный дизайн, написан руками поверх | **ДА** |

Базовый слой сломан намеренно: в переопределяющем `:root` стоит `--color-primary-500: #ffffff`,
`--color-primary-600: #f5f5f7`, `--color-primary-700: #5A5B62`. Все «primary»-стили шаблона
(`.btn-primary`, `.pricing-card--featured`, `.stat-card__number`, `.text-label`) дают белое на белом.
В `.pricing-card` / `.testimonial-card` / `.stat-card` уже лежит готовая вёрстка тарифов и отзывов —
**не брать**, это чужая дизайн-система с другими радиусами, отступами и тенями.

### 0.2. Fluid vw вместо rem

Ни одного `rem` в живом слое. Всё считается от ширины макета:

```
desktop  (≥1024px)  calc(N / 14.4 * 1vw)   // макет 1440
tablet   (768–1023) calc(N / 8.1  * 1vw)   // макет 810
mobile   (≤767px)   calc(N / 3.75 * 1vw)   // макет 375
```

`N` — размер в пикселях из макета. Например, заголовок секции 52px на десктопе → `calc(52 / 14.4 * 1vw)`.
Масштабируются так же font-size, padding, gap, border-radius, letter-spacing.

Вспомогательный хелпер (положить в `shared/lib`):

```ts
export const fluid = (px: number, base: 14.4 | 8.1 | 3.75 = 14.4) =>
  `calc(${px} / ${base} * 1vw)`;
```

Выше 1440px и до 2560px есть отдельный `large-screens.css`, который переводит фиксированные px
в те же vw, чтобы макет не отставал. Выше 2560px всё замораживается: `body { max-width: 2560px; margin-inline: auto }`.
**Это можно не воспроизводить** — в ТЗ верхняя граница 1280px. Написать в README как осознанно пропущенное.

### 0.3. Нет контейнера

Никаких `max-w-7xl mx-auto`. Секции full-bleed, ограничены только горизонтальными паддингами:

```
desktop  padding-inline: calc(40 / 14.4 * 1vw)
tablet   padding-inline: calc(20 / 8.1  * 1vw)
mobile   padding-inline: calc(16 / 3.75 * 1vw)
```

## 1. Токены

### 1.1. Цвета

```css
--background-primary:   #F2F2F4;   /* но! см. примечание ниже */
--background-secondary: #FFFFFF;
--foreground-primary:   #FFFFFF;   /* карточки */
--foreground-secondary: #FAFAFA;
--foreground-tertiary:  #F5F5F7;   /* неактивные табы, плитки */
--text-primary:         #000000;
--text-secondary:       #5A5B62;   /* описания, подзаголовки */
--text-tertiary:        rgba(0,0,0,0.6);
--text-contrast:        #FFFFFF;
--stroke-primary:       rgba(0,0,0,0.05);
--stroke-secondary:     rgba(0,0,0,0.4);
--stroke-tertiary:      rgba(0,0,0,0.1);
--divider:              rgba(0,0,0,0.06);  /* линии в таблице сравнения */
```

**Примечание про фон.** В базовом CSS `--color-background: #F2F2F4`, но кастомный слой перебивает
на `#f5f5f6` (`html, body, .dds-footer`). Живое значение — **`#f5f5f6`**. Разница в 3 единицы
незаметна глазом, но если возьмёшь `#F2F2F4`, на стыке с футером будет видимый шов.

### 1.2. Брендовый градиент

Единственный цветной акцент на всём сайте. Три применения:

```css
/* 1. Текст кнопок и акцентных слов — 90deg */
--brand-gradient: linear-gradient(90deg, #ff6d3c 0%, #ff6ba7 46%, #bb6dff 100%);
/* применяется через -webkit-background-clip: text; -webkit-text-fill-color: transparent */

/* 2. Заливка больших карточек — 157deg, почти пастель */
--brand-surface: linear-gradient(157deg,
  #fff 17.71%, #ffcdb3 43.16%, #ffa4b6 58.2%, #ffb2e9 73.32%, #d4d6ff 90.8%, #fff 103.16%);

/* 3. Градиентная рамка (mask-composite) — 135deg */
--brand-border: linear-gradient(135deg, #ff6d3d 0%, #ff6ca7 52%, #bb6dff 100%);
```

Приём для рамки (колонка «снэпбилд» в таблице сравнения):

```css
padding: 2px;
background: var(--brand-border);
-webkit-mask: linear-gradient(#fff 0 0) content-box, linear-gradient(#fff 0 0);
-webkit-mask-composite: xor;
mask-composite: exclude;
```

Больше цветных акцентов на сайте нет. Ни синего, ни зелёного, ни цветных иконок.

### 1.3. Шрифт

`TT Commons Pro`, начертания 300/400/500/600/700, `font-display: swap`.
Фактически используются **500 и 600**, изредка 550 (заголовок секции безопасности).

> ⚠️ Шрифт коммерческий. Копировать `.woff2` с их сервера в публичную репу — юридически спорно.
> Варианты: (а) подключить с их CDN, (б) заменить на близкий бесплатный гротеск и честно
> написать в README «что не удалось и почему». Второе безопаснее и, судя по критериям, зачтётся
> как внимание к деталям. Ближайшие по рисунку: Manrope, Onest, Golos Text.
> В fallback-цепочках сайта местами торчит `"Satoshi Variable"` — остаток шаблона, не воспроизводить.

### 1.6. Тени

Почти нет. `--card-shadow: none`, `--btn-shadow: none`.
Единственные живые:
```
шапка при скролле:  0 6px 22px rgba(29,22,40,0.055)
пилюля в hero:      0 4px 16px rgba(0,0,0,0.04)
```
Разделение блоков — заливкой и рамкой `rgba(0,0,0,0.06)`, не тенью. Это важная черта стиля.

### 1.7. Брейкпоинты

```
--breakpoint-md: 768px
--breakpoint-lg: 1024px
--breakpoint-xl: 1440px
```

Логика: `≤767` мобилка, `768–1023` планшет, `≥1024` десктоп.
ТЗ требует проверить 1280 / 768 / 375 — все три попадают внутрь этих диапазонов, отдельный
брейкпоинт на 1280 не нужен.

### 1.8. Анимация

```css
--motion-ease: cubic-bezier(0.16, 1, 0.3, 1);
--dds-btn-ease: cubic-bezier(0.4, 0, 0.2, 1);
--dds-btn-dur: 0.4s;
```

Reveal при скролле — на каждой секции:
```css
.dds-reveal { opacity: 0; transform: translateY(32px);
  transition: opacity .9s var(--motion-ease), transform .9s var(--motion-ease); }
.dds-reveal.is-visible { opacity: 1; transform: none; }
```
IntersectionObserver: `threshold: 0.12, rootMargin: "0px 0px -8% 0px"`, `unobserve` после срабатывания.
Везде уважается `prefers-reduced-motion: reduce`.

Микровзаимодействия:
- `:active` на кнопках → `scale: 0.975`
- hover на кнопке с градиентным текстом → пробег блика по тексту (`background-position` 400% 100%, 0.75s linear)
- hover на табе → фон `#ebebee`

### Приёмы, которые стоит повторить

**Табы и аккордеон — на чистом CSS.** `input[type=radio]` / `[type=checkbox]` спрятаны, состояние
через `:checked ~ .sibling`. Аккордеон раскрывается через `grid-template-rows: 0fr → 1fr` —
это позволяет анимировать высоту без JS и без фиксированных значений. В React логичнее сделать
на `useState`, но механику раскрытия через grid-rows сохранить, она даёт ту же плавность.

**Автоплей в use-cases.** `requestAnimationFrame`, 8000ms на пункт, 4 пункта на таб, после
четвёртого — переход на следующий таб по кругу. Прогресс рисуется `transform: scaleX(0→1)`
на полоске под карточкой, заливка — брендовый градиент. Клик по карточке или табу сбрасывает таймер.

**Дублирование текста в разметке.** Почти у каждого заголовка два спана: `.dds-steps-wide` и
`.dds-steps-narrow` с разными переносами под десктоп и мобилку, переключаются `display`.
В React это делается одним компонентом с двумя пропсами — но перенос строки под мобилку
воспроизвести стоит, он влияет на «переносы текста» из критериев оценки.

**Marquee.** На десктопе (`≥768px`) анимация **отключена**, логотипы просто центрируются:
`animation: none !important`. Бежит только на мобилке, 12.1s, `translate3d(0 → -50%)`, и стартует
только когда секция в зоне видимости (IntersectionObserver ставит `animation-play-state: running`).

**Шапка.** `position: fixed`, `pointer-events: none` на секции и `auto` на самой пилюле —
чтобы клики проходили сквозь прозрачные поля по бокам. При `scrollY > 12` добавляется `.is-scrolled`,
появляется тень и рамка. Ширина пилюли `min(100% - 32px, 960px)`, фон `rgba(255,255,255,0.8)` + `blur(10px)`.

**Мобильное меню** — фуллскрин `position: fixed; inset: 0`, ссылки выезжают лесенкой
с задержками 40/85/130/175/220ms.

**Таблица сравнения на мобилке** — горизонтальный скролл, первые две колонки `position: sticky`.
Градиентная рамка второй колонки рисуется через `background-size: 100% 348px` с разным
`background-position` для каждой строки — чтобы градиент не перезапускался в каждой ячейке.
Приём тонкий; если времени нет, на мобилке рамку можно скрыть (в оригинале так и сделано
для части случаев) и написать об этом в README.

### 3.5. Форма запроса демо — `#demo`, перед `cta`

Структура: две колонки — слева заголовок, подзаголовок и 3 буллета «что будет на демо»,
справа карточка формы (`#fff`, radius 24, padding fluid(32)). Мобилка — одна колонка.

Поля (`--input-radius: 20px`, `border: 1px solid rgba(0,0,0,0.1)`, фокус — рамка брендовым цветом):

| Поле | Тип | Валидация |
|---|---|---|
| Имя | text | обязательное, ≥2 символов |
| Рабочая почта | email | обязательное, regex, отдельная ошибка на публичные домены («укажите рабочую почту») |
| Компания | text | обязательное |
| Размер команды | select | 1–10 / 11–50 / 51–200 / 200+ |
| Задача | textarea | необязательное, ≤500 символов со счётчиком |
| Согласие на обработку данных | checkbox | обязательное |

Поведение:
- валидация по `blur` и по submit, **не** на каждый keystroke — иначе ошибка загорается, пока человек ещё печатает;
- ошибка под полем, 14px, рамка поля красная, `aria-invalid` + `aria-describedby`;
- на submit — состояние загрузки 600ms (имитация), затем success-состояние вместо формы:
  заголовок «Заявка отправлена», текст «Свяжемся в течение рабочего дня. Если срочно — напишите в Telegram»,
  кнопка «Отправить ещё одну»;
- реальной отправки нет, в README указать явно.

Тексты: заголовок «Посмотрите на своей дизайн-системе», подзаголовок «Покажем платформу на ваших
компонентах и соберём один реальный материал прямо на встрече».
Буллеты: «Разбор вашей дизайн-системы» · «Живая генерация страницы и баннера» · «Ответы по контуру и 152-ФЗ».

## 4. Чего не делать

- Не тянуть `.card`, `.pricing-card`, `.testimonial-card`, `.stat-card`, `.btn-primary`, `.section-header` из базового CSS — это другая дизайн-система с битыми токенами.
- Не заворачивать секции в контейнер с `max-width`.
- Не переводить размеры в `rem` — сломается совместимость с соседними секциями при ресайзе.
- Не добавлять тени карточкам. Разделение — заливкой и рамкой `rgba(0,0,0,0.06)`.
- Не добавлять цветных акцентов, кроме брендового градиента.
- Не тащить `features` в FSD ради формы — форма это внутренность виджета `demo-form`.
- Не повторять паттерн табов в новых секциях (занят `use-cases`).
